# Сборка базового образа

## Что создаётся

Профиль `base-amd64` готовит консольные установочные носители из текущего
чистого коммита AmeOS: disc1/bootonly ISO, memstick/mini-memstick и наборы
дистрибутива. Для установки без сети используйте **disc1 ISO или полный
memstick**, а не bootonly/mini-memstick. AmeDE, Wi-Fi firmware из пакетов
и дополнительные приложения в профиль пока не входят.

Файлы носят префикс `AmeOS-0.1-dev-amd64`, но внутреннее оформление,
установщик и версия ОС остаются FreeBSD. Переименование файлов не означает,
что desktop-интеграция завершена.

## Среда

Полный процесс рассчитан на отдельную **FreeBSD/amd64 VM**
с Git и стандартными средствами разработки и создания образов. Выбирайте
хост, совместимый с зафиксированным CURRENT, и читайте корневой `UPDATING`.
Компактный профиль подтверждён полной сборкой на FreeBSD 15.0-RELEASE/amd64.

Измеренная конфигурация компактного профиля: 2 vCPU, около 3 ГиБ RAM,
без swap, `--jobs 1`, ограничение виртуальной памяти отдельного процесса
2048 МиБ. Полный процесс занял 38 ч 25 мин. После сборки объекты занимали
около 6,7 ГиБ, снимок исходников 699 МиБ, артефакты 1,3 ГиБ по `du` на ZFS.
Это не измерение пикового расхода и не минимальные требования.
Больший диск и RAM полезны для скорости и повторных сборок, но 100 ГБ
не являются обязательным условием. См. [протокол](validation-2026-11.md).
Число jobs по умолчанию равно 2; для небольшой ВМ указывайте `--jobs 1`.

Windows/Git Bash поддерживает `--plan` и тесты управляющего скрипта.
Полная компиляция и создание носителей на Windows не поддерживаются этим
скриптом. Наличие WSL не заменяет FreeBSD VM.

## Получение исходников

```sh
git clone https://github.com/ntych/AmeOS.git
cd AmeOS
git switch <ветка-с-изменениями-AmeOS>
git status --short
git rev-parse HEAD
```

Если изменения подготовлены локально, сначала проверьте и закоммитьте их
в рабочую ветку. Сборка использует **только HEAD**, включая профиль и скрипты,
а не незакоммиченные файлы. При грязном рабочем дереве полная сборка остановится.
Не сохраняйте логи и результаты внутри клона.

## Предварительная проверка

Из корня репозитория в POSIX shell:

```sh
sh ameos/scripts/build-release.sh --help
sh ameos/scripts/build-release.sh --plan --jobs 2 --workdir /var/tmp/ameos-base-001
sh ameos/scripts/build-release.sh --check --profile compact-amd64 --jobs 1 --workdir /var/tmp/ameos-check-001
node ameos/tests/build-release.test.mjs
```

Node.js нужен только для тестов, а не для самой сборки. На Windows тесты
можно запускать из Git Bash с установленным Node.js. При запуске Node напрямую
из PowerShell укажите путь к shell:

```powershell
$env:AMEOS_SH = 'C:\Program Files\Git\bin\sh.exe'
node ameos/tests/build-release.test.mjs
```

Режим `--plan` ничего не создаёт и не требует FreeBSD/root. Он проверяет
пути, параметры, профиль и наличие базового коммита в истории, выводит
конкретный HEAD и предупреждает о незакоммиченных файлах. Он не проверяет
компилируемость дерева или достаточность ресурсов хоста.

## Полная сборка в FreeBSD VM

Из обычного пользователя в чистом клоне, с доступным ему рабочим каталогом:

```sh
sh ameos/scripts/build-release.sh --jobs 2 --workdir /var/tmp/ameos-base-001
```

Родитель рабочего каталога должен существовать, а сам каталог — нет.
Пути должны быть абсолютными, без пробелов и специальных символов. Каталог
сборки должен находиться вне клона; скрипт разрешает символические ссылки
в родителе только после определения физического пути.

Этапы:

1. Сохранение Git-снимка исходников и извлечение в `src`.
2. `make buildworld` и `make buildkernel KERNCONF=GENERIC` с отдельным `obj`.
3. `make release` без ports, внешних пакетов и pkgbase.
4. `make install DESTDIR=.../artifacts` **в release-каталоге** для копирования
   носителей; установка world/kernel в корень хоста не выполняется.
5. Проверка наличия полного ISO и USB-образа, запись контрольных сумм.

Скрипт не вызывает `release/release.sh`: это исключает его стандартное
получение исходников из другой ветки и позволяет использовать локальный
зафиксированный коммит. Не передавайте профиль AmeOS как `release.conf`
этому upstream-скрипту — у них разные интерфейсы.

В процессе сборки скрипт не вызывает загрузку пакетов или исходников из сети.
Подготовка хоста и получение Git-клона выполняются отдельно.

## Результаты и ошибки

```text
/var/tmp/ameos-base-001/
  src/
  obj/
  buildworld.log
  buildkernel.log
  release.log
  install.log
  artifacts/
    BUILD-INFO.txt
    base-amd64.conf
    base-amd64.src.conf
    AmeOS-0.1-dev-amd64-disc1.iso
    AmeOS-0.1-dev-amd64-memstick.img
    ...
    CHECKSUM.SHA256
    CHECKSUM.SHA512
```

Логи этапов создаются по мере выполнения. Ошибка немедленно завершает процесс;
каталог сохраняется для диагностики. Наличие `BUILD-INFO.txt` само по себе
не означает успеха. Повторная попытка использует **новый** рабочий каталог.
Автоматического удаления старой сборки нет.

Промежуточный `source.tar` удаляется после успешного извлечения: исходный
чистый коммит позволяет создать его заново. Остальные результаты сохраняются.

## Компактный профиль и проверка на небольшой ВМ

`--profile compact-amd64` отключает отдельные отладочные файлы userland,
установку символов ядра, тестовые наборы и необязательные архитектуры LLVM. GENERIC и его
драйверы сохраняются. Компилятор не подменяется автоматически: исходники
CURRENT требуют своей версии toolchain. Цена компактности — меньшая
диагностическая информация и отсутствие установленного набора тестов.

```sh
sh ameos/scripts/build-release.sh --plan --profile compact-amd64 --jobs 1 --workdir /var/tmp/ameos-compact-001
sh ameos/scripts/build-release.sh --check --profile compact-amd64 --jobs 1 --workdir /var/tmp/ameos-compact-001
```

`--check` дополнительно проверяет FreeBSD/amd64, инструменты, чистоту исходников,
доступное место, RAM и swap. Это проверка предпосылок, а не обещание, что
компиляция поместится. Перед созданием рабочего каталога и перед каждым
крупным этапом требуется хотя бы 2048 МиБ свободного места. Проверка выполняется
между этапами и не ограничивает расход диска внутри выполняющегося make.
При малой RAM без swap выводится предупреждение. В проверенном запуске
перед сборкой было около 14,6 ГиБ свободного диска; полный выпуск создан.
Условия и ограничения приведены в протоколе.

Обязательная проверка root снята: release использует `NO_ROOT` и METALOG для
описания прав внутри образа. Системные пакеты и настройки хоста этот скрипт
не меняет; для их подготовки может потребоваться администратор.

Перед длительной сборкой можно проверить реальные инструменты без root:

```sh
sh ameos/scripts/check-native.sh --workdir /var/tmp/ameos-native-001
```

Проверка собирает и запускает `bin/echo` из текущих исходников с библиотеками
хоста, затем создаёт маленькую UFS-файловую систему и GPT-образ с тестовыми
данными. Она сохраняет логи и `PROBE-RESULTS.txt`. Это проверка native-сборки
одной утилиты и инструментов создания образов; она не заменяет `buildworld`,
сборку ядра, установку или проверку загрузки. Созданный образ не загрузочный.

Контрольные суммы подтверждают целостность, но не подлинность. Подпись образов
нужно добавить до публичного распространения. Для строгой воспроизводимости
ещё предстоит сравнить две сборки и зафиксировать версию хоста/toolchain.

## Загрузочная проверка

Проверяйте носители в отдельной VM с пустым виртуальным диском:

- Загрузка disc1 в UEFI и, отдельно, BIOS.
- Доступность консоли и запуск установщика.
- Установка на виртуальный диск из локальных наборов, без сети.
- Перезагрузка с виртуального диска, вход, проверка версии и сети.
- Отдельная проверка полного USB-образа.

Сохраните коммит исходников, настройки VM и результаты. Успех компиляции
не заменяет эти проверки. Результаты выполненной сборки и загрузочных тестов
зафиксированы в [протоколе валидации](validation-2026-11.md).
